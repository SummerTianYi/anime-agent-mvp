## 原因核对及最小改动

原有基线的 `after-joy-2` 是助手自己提出再弹一次。用户随后夸“小天才”，接着借帽子给她；`after-joy-3/4` 的 DS 可见正文已经含有“那第二遍试了吗？”和“不过帽子先放一边——第二遍弹了没？”。日常分享的前四轮也接连索要更多细节或邀请用户确认感受。低落组则在用户明确拒绝建议后收住。历史包里同时存在这些正、反例。[历史请求](../companion-platform/requests.jsonl) · [历史气泡](../companion-platform/dialogues.jsonl)

`handle_chat → _companion_turn → model_history → CharacterHarness.build_messages → provider.complete` 保留了近期用户、助手的实际发言。历史助手回答按既有 JSON 合同编码，先前自己提出的练习仍在可见上下文里。之后的 normalize_voice_text 和记忆承诺过滤没有生成追问。本轮 28 个返回的可见原文均交给实际解析器，解析出的 reply、最终气泡及语音入口 28/28 逐字一致。由此可以定位追问出现在模型生成阶段。历史会使旧建议格外显眼是可检验的假设；现有结果不能把模板化归因于某个冻结的人设段、训练语料或单一模型参数。

候选只给陪伴通道增加一段 203 字符的运行策略。它区分用户当下的意图与助手自己之前的提议，保留用户转题、暂时不求解和后来主动求解的空间。在 `conversation_context.companion_context` 中，策略在前，已有的有效记忆数据块在后；`_companion_turn` 将它交给原 Harness。任务通道、授权、记忆写入和输出解析继续走原路径。没有按标点过滤回复、限定句数或统一截短；测试里模型返回的真实问句会原样交付。没有把测试中的道具、曲目或练习措辞写进策略。

## 真实试听与自动回归

官方 DeepSeek 共 **28/32 次**，基线 8 次、候选 20 次。全部经过隔离 `handle_chat`、既有 Provider 及发送前统一计数。模型标识 `deepseek-flash`，thinking=disabled，入口 effort=deep；没有修改采样参数。失败、重试、工具派发均为 0。请求耗时累计 70.018 秒，输入 54,975、输出 2,337 tokens。试听使用这批真实回复的原文，额外模型请求 0。所有场景和历史均为合成数据。[用量与验证](verification.json)

试播经过实际 `_present → _speak_reply → SpeechManager → 已有 sidecar → 隔离 WebSocket → 可见 Godot 角色 → WASAPI`。使用本轮候选的 runtime、interaction_ui、speech_output 和 main.tscn；每个文件与隔离工程核对过。角色加载 703 骨、48 个表情形态，观测到 1528 个播放帧和 0.72 嘴形峰值。两条分别收到了 2、4 个有效分段回执。第一条两段之间有 **1.887 秒**，第二条相邻段之间有 **0.011、4.537、0.013 秒**；这是前一文件播放结束至下一文件开始的时差，不含 WAV 内部静音。用户原话为“听到了，但语气或衔接不自然”。较长空档值得定位，现有主观反馈没有指明某一段或单一原因。两条以外的真人听感待验收。[回执、分段时序与人听反馈](audition.json)

试播前后正式 Core、Godot 与 TTS 的 PID 均相同；预取 1，角色增益 +5 dB，Whisper 自检启用且阈值 0.9。共享 sidecar 合成计数从 15 到 24，隔离窗口正常接入也触发其既有启动问候事件和三条告别预缓存，六个试听文件有独立回执。未加载第二套模型。回执确认播完，试听自然度按所有者反馈单独判定。

## 复现与回退

1. 使用本候选和上述基线各一份独立检出，Python 3.12 与仓库 Core 依赖。普通核对只需在最终候选执行 `python docs/assessments/companion-experience-p0/verify_evidence.py`，禁网即可重算 28 次正文、八对完整请求、连续历史和有效人设指纹。它不评判语气。
2. 若另获新一轮真实配额，在仓库外新建空目录，创建空标记文件 `synthetic-only`。使用本目录 `evaluate.py --phase before --repo <基线> --state <同一隔离目录> --ds-env <本机官方配置>`，然后 `--phase after --repo <候选>`。两阶段复用同一计数文件、进程锁和传输层硬限，严禁重置计数续跑本轮。DS 非确定性，重算完整输入不保证逐字相同输出。
3. `observe_edges.py` 在临时库输出三个路由问题和恢复通知。`observe_switch.gd` 可用 Godot 无头、独立工程和不可达的测试 WS 端点 `ws://127.0.0.1:1/ws` 重现旧回执进入新页。在有维护余量的开发机，将本轮对话给 `audition.py --repo <候选> --state <新的空标记目录> --godot <Godot 4.7.2> --project <含本人本地角色及独立用户目录的副本> --dialogues <dialogues.jsonl>`，脚本仅使用已有本地 sidecar。
4. 候选产品改动集中于 `agent_core/conversation_context.py`、`agent_core/main.py` 的陪伴装配和 `tests/test_companion_channels.py`；分支上反向提交 `0b951016` 可撤回。main 的提示词如需恢复，单独反向提交 `cf62b484`。两者互不依赖，无数据库迁移。UI 复刻、Agent 执行重构、P2 和正式部署继续留待独立决策。

后续体验实验可单独比较“如何在历史中表达助手提出、用户未采纳的建议”，以及同一段文字在不同分段间距下的真人听感。本轮没有借此扩大产品改动。等待 ChatGPT 独立复验。
