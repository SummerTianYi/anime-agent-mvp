### 根因及修复

1. **问题在进工具环之前就可能丢失。** 固定候选按“操作动词加目标”识别任务。F1 原句走陪伴通道，能调用搜索的路径根本没有运行。显式“搜索网页”会进工具环，但 MCP 默认 ask。只读分类用于结果语义，不能给固定供应方、用户意图或具体参数提供授权证明。现场“取时间后出现两行搜索”与固定提交上的原句走了不同路径。现场没有可用于逐项配对的参数和任务，不能据此断言重复执行。
2. **公开查询采用受约束的外发。** 主路径由 Core 自己调用固定的 Tavily HTTPS 搜索端点，禁止重定向。权限引擎核对用户来源、会话、任务、参数结构和本轮公开主题。支持赛程、积分、奖项、公开事件和显式给定的公开检索词。单说“查积分榜”又没有相应赛事上下文时，先问是哪项赛事。搜索参数从公开词项构造，不携带历史、邮件地址或私人事实。部署配置中的 Tavily MCP 是可更新的启动器，未把其名称、前缀或 readOnly 提示当作能力证明。旧 MCP 搜索仍须批准，关键词须来自本轮明确要求，附加私人筛选项会在制票前被拒绝。私人 MCP、截图外传、命令、写入继续走各自权限规则。[范围投影及传输](../../../services/agent-core/agent_core/public_search.py) · [权限引擎](../../../services/agent-core/agent_core/permissions.py)
3. **确认需要同时保住原问题和动作的所有者。** 原客户端会把队首票据附给普通消息。宿主可能在批准后重新规划，又把无新增步骤的回答判为没有回执。现在批准绑定到展示过的动作、参数哈希和版本，执行时再对账本会话、任务、时效和现行权限复核。单项支持“同意”，多项需明确序号。读结果回到最初的问题，已成功的读取可与后续的收件人澄清或发送预览同轮交付。旧内容、拒绝、过期或结果未知都不能授权重发。[动作账本](../../../services/agent-core/agent_core/actions.py) · [Core 调度与交付](../../../services/agent-core/agent_core/main.py)
4. **工具回执曾同时承担诊断和正文。** 原 `_receipt_delivery` 把工具名、参数 JSON、结果引用和确认手册拼进正文。Godot 又按 `ok` 把待确认画成失败，TTS 接收的是同一份污染文本。现在历史事件保留完整执行关系，普通回答只取已核实内容、对象、状态、来源及查询日期。Godot 的工具卡默认关闭，诊断模式区分等待、失败、取消和结果未知。语音读来源站名，气泡保留可打开的 URL。用户明确索要的 JSON、代码和单位按原文保留。[交付投影](../../../services/agent-core/agent_core/action_delivery.py) · [窗口事件入口](../../../apps/avatar-runtime/runtime.gd) · [实际聊天控件](../../../apps/avatar-runtime/interaction_ui.gd)
