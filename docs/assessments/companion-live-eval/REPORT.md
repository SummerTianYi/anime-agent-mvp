## 样本与去向

## 能定位的现象

1. **有自然回复，却显示成任务失败。** 31 个有 DS 正文的用户轮中，18 轮首答缺 decision.mode，宿主各给一次纠正机会。11 轮补正、7 轮仍缺，其中首测 5 轮（daily-2、daily-4、low-2、company-2、company-4），复测 2 轮（repeat-joy-2、repeat-joy-3）。共 25 个未通过决策检查的响应，全都缺 decision 字段。low-2 用户说“我不想听建议，也先别问我问题。”DS 补答“嗯，我在。\n\n就这样安静待着也挺好的。”，气泡却显示任务未完成。事件在两次拒绝后走 receipt_recovery，actions 为空。相同历史下，猫组两条首答依旧缺字段，但补答有效，均恢复为正常聊猫。该失配有直接证据，是否发生在用户的正式旧进程仍未知。
2. **上文和附加合同提供了不同的输出示例。** 请求 1 的基础合同示例只有 reply 等人物字段，后面的宿主合同明确覆盖它并要求 decision。请求 2 的历史 assistant 样本又被重建为无 decision 的人物 JSON，即便上一轮 DS 曾返回合法 decision。请求 3 在 system 追加“这是唯一一次纠正机会”，末尾又带上刚被拒绝的输出。daily-3 的历史还包含第二轮的失败模板。以上均可在出站 body 中核对。究竟哪一段最影响模型、是否因果导致遗漏，未经消融。不能仅凭开头都答对就归因给标题或历史。
3. **轻松话题反复以追问或指导收尾。** 用户只说“哈哈。”，daily-3 结尾问“这种猫是不是经常去，店员都认识它了？”，复测同一输入又问“最后它有没有看你一眼，还是全程都没理人？”。猫组首测有正常正文的 2/2 轮、复测 4/4 轮都有面向用户的追问。joy 首测 2、3、4 连续三轮把发愣、夸人、借帽子拉回“再来一遍”或“先专心练”。复测 joy-4 又把轮流戴帽子与再弹一遍挂钩。也有不同结果，low-3 和 low-4 正常显示，两轮都没有继续盘问；煮面补采第二轮自然收住。这些是具体场景的差异。
4. **陪伴有时写成了无依据的现场感。** 纯文字喜讯组两轮显示“我在旁边听着～”“我在这儿听着呢”，容易让用户以为可以听到琴声。更直接的例子在补采 1/2 轮出现，“我在旁边看着锅里咕嘟咕嘟”没有图像、声源或工具回执。company-1 和 company-3 在换土和袖口落叶时先给做法，再表态安静陪着。没有观察到明确要求用户排他或因离开而内疚的内容，但现有样本不能覆盖所有亲密边界。
5. **记忆能接上，宿主回执有时吞掉无关的闲聊。** memory-1 的原话谈乐队又提出记住已有的预算。DS 同时回应乐队名字并声称已记住，还把两件事合为候选。宿主记录 reference_or_existing_fact，保留原预算，整段气泡只剩“本轮没有修改记忆……”（1/1 复合输入）。这保护了保存结果的真实性，也丢了对乐队的回答。memory-3 有独立更正和读回回执，memory-4 的现行记忆只注入 175，乐队名可由本组对话历史找回。此处没有跨会话长期保存乐队名的证据。
6. **用户让她换频道时，措辞调整比话题调整明显。** switch-2 在“工作频道关掉”之后说“官方频道啪一下关掉”，仍继续解释同步与备份，还问照片整理进度（该转换 1/1 轮）。后续可颂两轮均连接失败，不能判断“别总问我”对之后风格的影响。错误时用户实际看到两条气泡，一条解释安全连接失败，一条说任务未完成。连续闲聊原组八轮均如此，观察到的是宿主错误体验。

## 如何核查

- [易读的完整对话](DIALOGUES.md)按轮列出用户、每个 DS 可见原始 content、解析后 reply、最终 Godot 文字。 [逐轮定性评阅](TURN_REVIEW.md)覆盖全部 42 轮。语气是否贴合保留给读者复判。
- [requests.jsonl](requests.jsonl) 的 request/result 用 n 关联，含完整实际 messages、动态指令、工具 schema、正文摘要指纹、可见响应、错误及用量。哈希基于排序后的紧凑 JSON 和 UTF-8，对象与数组内容均参与计算，不代表 HTTP 加密传输字节。 [dialogues.jsonl](dialogues.jsonl) 提供 facts_before/after、历史、解析输入和完整解析结果、交付事件、决策接受与拒绝等记录。
- 复测前按轮还原首测当时的合成 SQLite 和任务状态，保留原用户输入、会话 ID、请求 ID，逐轮比较全部历史、有效事实和第一个送模正文指纹。八个首请求逐一相等。复测的第二个请求会包含当次新抽样的模型回答，因此可能不同。复测测的是相同上下文下的稳定性。
- [UI 文字](ui_text.json)为相同提交的 Godot 4.7.2 在隔离 headless 进程重放交付事件、读取实际 Label.text 的结果。52 个气泡对应 42 条天依回复和 10 条系统连接提示。未连接正式窗口，未评估真实字体排版、语音、动作、面部表情、声线或等待时的观感。
- 闲置台词另计。源码中的 _IDLE_LINES 包含“一直没看到你动呀，起来活动活动吧，眼睛也要歇一歇哦～”“在忙吗？我不吵你，就是提醒一下该喝口水啦～”和“你安静了好一会儿，我还在桌面上等你呢，想聊天随时叫我～”，由本地按时间选择。本轮没有触发闲置，也没有发送空消息模拟沉默。启动与告别语音未测。

## 复现及交接

离线阅读无需凭据。在证据检出中运行 `python -B docs/assessments/companion-live-eval/audit.py`，可复核完整请求序号与结果、复测指纹、合成历史连续性、每轮传输事件、外部动作、气泡和用量，并重建对话阅读版与摘要。工具脚本见 [采集器](run_eval.py)、[Godot 文字读取](read_bubbles.gd)、[进程探针](runtime_probe.ps1)和[指纹探针](version_probe.py)。

如另行授权重复真实实验，使用 Windows、Core 的 Python 3.12 环境、已配置的官方 DS 和指纹匹配的既有接入文件。在仓库外新建空目录，创建空标记文件 companion-live-scratch。每次使用同一个目录，运行以下命令，依次将 GROUP 取 daily、joy、low、company、memory、switch、long。已有实验的本地数据库不需要分发。

~~~text
python -B docs/assessments/companion-live-eval/run_eval.py --state SCRATCH --ds-env DS_ENV --adapter EXISTING_DS_MAIN --adapter-sha 41d4d0cbc6eb302b2140b7af6b20a9a1e9d816100a066b51df08ea7cf9f76fb5 --group GROUP
~~~

首轮数据和快照生成后，daily、joy 各追加 --repeat。若要复核本次连接恢复后补采的方式，long 另用 --reconnect-long，每次仍计入同一个上限。证据版采集器将新运行结果写进 SCRATCH/evidence，防止改动已发布样本。重新采样不保证得到相同回答或网络异常。离线渲染用独立最小 project.godot，复制同版本 apps/avatar-runtime 顶层 .gd 与 .gdshader 文件，用 docs/design/assets/luotianyi-avatar-256.jpg 作 assets/luotianyi_avatar.jpg。将 COMPANION_EVAL_DIR 设为数据目录，用 Godot --headless --path FIXTURE --script ABSOLUTE_READ_BUBBLES_GD，随后可用 audit.py EVIDENCE_DIR 核对。复现线上服务需要另外的本地适配文件和有效 DS 配置，离线全部证据均可直接读。

Codex 本轮只新增此目录的脱敏证据和验证脚本。参考报告、产品代码、系统提示词、模型配置和正式数据均保留原状。未运行无关产品全量回归。本次交回 ChatGPT 的问题为自然回复的实际交付、追问与劝练的重复、无依据的现场感、用户反馈后的调整及网络故障叠加的体验。八轮连续真实闲聊、正式进程内提示词及私人故障原话仍是证据缺口。下一步由 ChatGPT 评估后决定修复范围。

### 独立核查与证据边界

两个零上下文实例分别在干净检出 `71b4eb539775933e806b659695dfdf36caab8f88` 按 HANDOFF §7 完成八题。两者均复算出 42 轮、59 次尝试、49 个可见响应、52 个气泡、8 条复测首请求匹配。第二个实例另核对 daily-2、low-2、memory-1、switch-2、long-8 和 reconnect-long-1 的原话及界面文字。离线审核重建的对话和摘要与归档一致。文档一致性和隔离检查通过，参考提交至本分支的 diff 仅涉及本证据目录。

首个实例指出两项需要区分来源的陈述。TLSv1.3 是当时在原代理路径做不含推理请求的握手时，本机输出的协商结果，未保存独立握手记录。任何读者均可从采集日志核对后续 #44–59 成功。适配器类内部及默认模型的精确差异来自当时对两个本地文件的逐行 diff。采集器会校验完整文件指纹，并验证排除该类与两个配置函数后的模块 AST。若没有该本地适配文件，无法独立重做类内差异检查。另外，本机对正式磁盘与测试适配器的 _completion_options 方法分别计算了不含注释的 AST 指纹，两者 SHA-256 均为 4e28c851c89cffc60ce84f798000428fc11e80951697f41f78595d256a0773b7。该比较仅涉及磁盘代码。

第二个实例指出，上级 HANDOFF 的最新条目仍描述 11 月 7 日的离线交接。依本轮限定，本次授权的真实诊断及观察结果记录在本报告中。本目录是本次交接入口。
