# 陪伴与 Agent 通道验收候选

天依现在可以在一项操作等待模型时继续聊另一件事。普通聊天只向官方 DeepSeek 请求一次正文；同一条消息中有明确任务时，聊天正文和已核验操作回执分别交付。真实对话中仍有连续追问和把话题带回练习的现象。**测试完成，等待 ChatGPT 独立验收。**

按所有者的最新指示，聊天 UI 复刻暂停。候选只对现有 Godot 消息接收器做了 P0 所需的回执标记和迟到事件过滤。输入框、布局、皮肤和角色窗口沿用桌面版。正式桌面仍在运行本轮之前的代码。

## 根因与实现

| 环节 | 修前复现 | 候选行为 |
|---|---|---|
| 闲聊进入 Agent | 在已有权限的合成环境，给“店员还得从它旁边跨过去”返回附加工具提案，旧入口可登记待确认票据。慢任务也会占用全局聊天锁。 | 本地判断明确操作才发工具请求。陪伴通道直接调用现有 Provider 的 `complete`，同一个人设 Harness 装配上下文，入口没有工具执行器或工具 schema。模糊、引述和假设默认留在聊天。 |
| 混合请求与取消 | 旧入口的操作回执可以占用整条聊天正文。 | 可分开的社交与操作子句分别处理，只保存一次原始用户输入。操作结果由原账本和读回记录交付，回执带会话、请求与任务标识。取消先撤销待确认授权，再次检查在途结果的所有者；已经派发的结果保留其真实状态。普通换话题保留待办。 |
| 记忆失败 | 复用历史“纸月亮／晨星120”回答，并按原条件预置有效事实。当前正式基线也只留下“本轮没有修改记忆”，乐队回应整段消失。 | 候选保留“纸月亮……这个名字真好听”，其后独立显示“本轮没有修改已有记忆”。写入失败时消除关于已保存的承诺。已有更正继续使用同一事务、版本、作用域和读回核验。 |
| 跨轮上下文 | 聊天携带操作预算、工具、既有任务状态；早发晚回的文字可能与另一轮混排。 | 陪伴侧只装配本会话有效聊天和相关可见事实。按用户行截取历史，按请求关联已经返回的答复；操作回执不伪装为新的模型消息角色。混合输入按通道投影。迟到正文留在来源历史，迟到任务结果不能抢占前台语音或角色状态。 |
| 无账本结果 | 某些明确操作以及“取消”仍可能得到模型自己的成功描述。 | 明确任务没有工具证据时，宿主交付“本轮没有取得可核验的操作回执”。无待办时的取消直接查账，不请求模型。没有接入通用 A4 回复核对器。 |

五条先行合成测试中，当前桌面源码有四条失败。拒绝建议不撤销现有票据的对照最初就通过。旧报告中日常和低落回答被“这次任务尚未完成”覆盖的问题，在已安装的这版回放中均未重现。三组修前与修后回放、记忆初态不同的对照均有记录。[逐轮输出](dialogues.jsonl)

## 人设冻结及运行设置

`services/agent-core/agent_core/harness.py` 的文件字节 SHA-256 在正式安装、隔离修前和最终候选三处均为 `331682df53bde9abfa6261a3856d90e98d8ed289131316b9856ca7dee5ebe820`。有效静态系统提示词的 UTF-8 SHA-256 为 `714ae650ce060f0a645f2fa1055878790438a5e93566ceda18a3ecbdc9d9c9f6`。40 个真实请求全部核对了该前缀。ROLE、RUNTIME 和 ACTIVE 各段指纹另附。相对正式桌面，人物描述、身份、输出字段、语气和动作枚举均未编辑。[有效提示词全文](../companion-v1.2/SYSTEM_PROMPT.txt) · [逐段指纹](runtime-persona.json)

修前 12 个普通聊天请求均有工具，系统文本中位数 3380.5 个字符；候选连续对话 18 个请求均无工具，中位数 2921。差异来自任务上下文、预算及工具指引退出陪伴通道，当前事实按数据装配，以及首轮沿用的标题指令。没有新增表达风格指令。[完整送模请求与可见响应](requests.jsonl)

正式进程的配置为官方 `deepseek-flash`，预取 1，语音增益 +5 dB，Whisper 自检启用且阈值为 0.9，免打扰为 01:00–07:00。正式机已有显式唤醒设置；候选沿用开关，默认手动按键录音，未写私人配置。静音时段缺省值与上述约定对齐。STT 语言、同闲置段只提醒一次、声线、自检、停顿和音频能量口型均沿用原实现。测试没有加载第二套 TTS。

## 真实对话与残留体验

所有输入均为合成数据，经隔离 `handle_chat`、现有 Harness 和真实官方 DS。40 次 HTTP 请求含所有任务循环、补答和标题，39 轮真实用户消息。调用总耗时 105.341 秒，Provider 报告输入 98,066 tokens、输出 3,065 tokens。网络失败 0。测试时 DS 的 `thinking.type` 均为 `disabled`，客户端 `deep` 只沿用工具预算。38 轮核心测试后，最后一条同历史复测专用于核对保留原换行的修正。[分组计数与复测](summary.json)

| 情境 | 实际表现 |
|---|---|
| 便利店的猫，连续 6 轮 | 修前自己补出“端着一箱饮料”，随后想到琴架。候选能接住门垫和绒毛，但前四轮连续提问。用户第 5 轮说“别总问我”后，末两轮接住“逗号可颂”且没有再提问。相同输入、历史的 `matched-daily-1` 仍问“它坐门口是不是在等谁呀？”。 |
| 弹完间奏、被夸和玩笑，连续 6 轮 | 修前借帽子的玩笑以“要不要趁手感热着再多弹几遍”收尾。候选第 3 轮问“那第二遍试了吗？”，第 4 轮又问“第二遍弹了没？”。第 5 轮用户说不练了，她同意换话题。去除任务预算没有解决练习联想与追问惯性。 |
| 汇报失利、拒绝建议和结束话题，连续 6 轮 | 修前、修后和同历史复测都尊重第 2 轮的明确边界。候选回应“好，我不问，也不说建议”，后面能转向雨停。第 2–6 轮中的“陪着你”“我听着呢”“我在这儿”仍有重复感。这个样本不能证明跨用户的长期改善。 |
| 混合任务、取消与预算更正 | 演出回应和文件任务回执分开。DS 在隔离工具边界先尝试查询目录，查询被拒，没有产生目标文件；没有将失败算作文件任务成功。第一次取消仍由模型措辞，修复后同类无待办取消使用宿主回执、0 次请求。晨星 120→175 产生真实事务回执，查询返回 175。初测多了一条无关记忆回执，修后同输入同历史的查询只剩正文。模型仍追问预算单位。 |

目前无法将追问单独归因于冻结的人设文字。历史回放还显示模型会添加未提供的具体细节。若另行授权调整风格，可用同一份“帽子／第二遍”和“门垫／简短回应”历史做单变量对照。本轮没有实施这类调整。

完整记录每轮用户输入、可见原始输出、解析后对象、气泡、喂给语音入口的文本及 Godot Label 读回。旧基线的思考填充语偶尔出现在下一轮等待期间，文本队列检测按原 requestId 留存。语音测试截取入队边界，未为这些对话逐条实际合成或试听。数据集中额外七轮是归档回放或对照，未计入实际模型消息。[完整对话和呈现](dialogues.jsonl) · [原始请求与可见返回](requests.jsonl)

## 组合验证与边界

- 最终 Core 全部 560 项通过，跳过 0。覆盖跨会话记忆更正与隔离重启、隐私/作用域、拒绝和确认、重试绑定旧票据、取消、同会话后台任务继续、授权前迟到提案不派发、记忆读写失败及坏 Provider 响应。TypeScript/Vite 构建、受限资产本地哈希检查和独立 WebSocket 通道验证均已运行。[机械验收记录](verification.json)
- 原版桥接脚本在修前与候选均超时；它要求最后三个状态连续为 thinking、speaking、idle。两版实际序列均为 thinking、idle、speaking、idle。隔离桥接分别验证了角色握手、菜单/动作路由、正文、合成 ACK 和播放结束回执；ACK 是合成客户端提供，不能作为真人听感证据。[桥接时序](bridge.json)
- 最终 Godot 的实际事件处理器和 Label 控件回放 49 条正文或回执，文本及回执标签逐条吻合。这是离线控件读回。所有者随后暂缓了 UI 复刻，隔离样机的输入、布局试作和截图不进入候选，真实桌面上的组合体验仍待单独验收。
- 最终修正还保留了原始段落换行。对 18 轮真实归档做离线线级复验，其中 13 个完整请求字节规范化后完全一致，5 个只差历史助理正文中的换行。16 轮气泡逐字相同，2 轮恢复模型原有换行；18 轮的文字和标点均一致。最后一条同历史真实复测见 `matched-joy-1`。没有重跑修后 18 轮真实序列。[逐轮等价性](summary.json)
- 对没有识别为明确外部操作的改述，入口保守留在陪伴侧，可能需要用户再明确对象或动作。外部业务未接通，未外发邮件、修改工单或读取私人会话。P2 长期关系建模、所有旧历史的语义清洗、完整 A4 验收仍待后续。
