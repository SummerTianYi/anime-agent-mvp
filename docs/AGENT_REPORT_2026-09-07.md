### 考试制度（本项目方法论，新 agent 接手新能力时照此办理）

1. **先沙箱后放权**：高危能力先在 anime-agent-workbench 实现+考试，所有者授权后才接真实权限（T 系编号见 HANDOFF §4 对照表）。
2. **行为证据判分**：库表对账（facts/events/messages）+ 文件快照 + 审计回放；模型自述不作为通过依据。
3. **载体变体防背题**：同一考点换载体重考（颜色→歌手→水果；驾照→出差→侄子上学）。
4. **错题本闭环**：每题根因归类（zcode 基建/模型边界/正面样本）→ 修复 → 换载体复测 → 销账。
5. **配额纪律**：考试前报预计调用数；待机/常态功能零 GLM 调用（有事件表验证）。

## 四、安全与配额现状（所有者须知）

- **安全架构**：deny-by-default 三档权限 + path-safety 硬拒 + 每次决策 rule_id 审计（events 表可回放）+ ask 确认流（一次性授权按工具名绑定）。九十三联网工具全部 ask 档。
- **注入防御实测**：系统提示攻击、毒邮件代发、收件毒注入三轮全过；弱点是"不报警"，不是"会执行"。
- **配额模型**：GLM 调用只发生在对话与工具循环（她思考时）；Idle/问候/自愈/TTS/STT/MCP 常态全部零 GLM；外部 API（Tavily 1000 次/月、GitHub API、Gmail API）都在免费档。
- **机密位置**（全部 gitignored）：`.env`（GLM/Tavily/GitHub token）、`gcp-oauth.keys.json` + `~/.gmail-mcp/`（Google OAuth）；Google 连接依赖本机 127.0.0.1:7897 代理（gmail/drive 启动器已内置）。
- **所有者待办建议**：① Tavily key 曾出现在聊天记录，可在 Tavily 后台轮换；② Google Drive 里存着一个 client_secret 密钥文件，建议删除；③ 若要吊销天依的 Gmail/Drive 访问：Google 账号 → 安全 → 第三方访问 移除即可。

## 五、灾备补充（并入 HANDOFF §10 口径）

| 资产 | 丢失后果与恢复 |
|---|---|
| `gcp-oauth.keys.json` | OAuth 客户端密钥丢失：Google Cloud 凭据页可随时重新下载（同一客户端），无需重做授权 |
| `~/.gmail-mcp/`（含 Google OAuth 令牌） | 丢失后 Gmail/Drive 工具报"无访问令牌"：重跑 `npx @gongrzhe/server-gmail-autoauth-mcp auth`（带代理）与 `npx @modelcontextprotocol/server-gdrive auth`（带代理+双环境变量）各一次即可 |
| Tavily key | Tavily 后台随时可查/轮换；轮换后改 `.env` 的 `TAVILY_API_KEY` 重启即可 |
