# 启动与退出修复验收（Codex，2026-09-11）

本轮已替换本地正式启动脚本，用户继续使用原来的 PowerShell 调用 `start-anime-agent.cmd`，不需要换入口或手动清端口。关闭 Godot 会结束对应 Core 进程树和会话守护；再次启动会自检、复用健康实例或在确认归属后恢复残留。官模、材质、动作和用户配置未改。所有者要求追加两轮高强度对抗，并在通过后授权收尾、提交和推送；最终结果见下节。上一轮因隔离账户执行/进程查询受限而暂停的候选状态已结束，本轮在用户正常 Windows 账户完成真实窗口验收。

| 根因与改动 | 实现及边界 |
|---|---|
| 健康 Core 被误报 | 原启动器限时2秒，详细 `/health` 又等待 TTS 探测；TTS缺席时实测约2.059秒，缓存命中仅16–31毫秒。新增不访问 TTS/LLM 的 `/health/live`，保留详细接口；仅旧版接口404时才回退到6秒详情探测，不把超时误当旧版本。 |
| 残留、并发与恢复 | `startup-common.ps1` 统一启动器/守护器的锁、探测和归属校验；启动宽限90秒、重复失败后恢复、限制重试，使用独立日志而非覆盖旧错误记录；Core在Godot加载途中死亡也会恢复。 |
| 关闭整个会话 | 守护持有明确 Avatar 代际的进程句柄；退出时在启动锁内重新检查是否已有新Avatar，防止旧守护杀新会话。终止前核对项目venv/父子关系、精确模块、PID与创建时间，再按树终止对应Core及子进程。恢复途中关闭Avatar会取消恢复。关闭窗口会中止该会话正在执行的任务。 |
| 就绪不是只有进程存在 | 检查可见窗口句柄、响应状态、Avatar WebSocket角色连接，并确认守护已初始化；旧ack必须匹配活的守护PID/创建时间与Avatar代际。重复调用保持一套实例。 |
| 空库初始化 | 全新数据库的历史响应原先含 `conversationId:null`，导致Godot `int(null)` 脚本错误；现用已有的空选择哨兵 `-1`，并增加回归。未改Godot视觉/动作代码。 |
| 终端与路径 | 保留 `.cmd` 入口，正确传递参数和失败退出码；Godot/守护的路径加引号、后台日志独立重定向。含空格的完整副本已实际启动。 |

## 审查发现、限制与回退

本轮三类审查分别检查了生命周期与子进程归属、并发/代际竞争、错误码/配置/真实UI就绪；没有启动子代理。首次副本复制失败是Windows长路径shader缓存，测试改为让副本重建该缓存；首次命令计时异常是Windows后台进程继承管道句柄，测试改用文件日志测父进程退出，避免把管道EOF误当命令完成。两者均保留失败记录，不计作通过证据。真实空库脚本错误不是忽略，而是补测试修复后重跑。

边界：陌生/归属无法确认的端口占用、文件缺失、访问被拒绝、无效配置会安全报错，不乱杀其它程序，也不假报成功。独立TTS侧车没有纳入本次守护，TTS缺席不阻止文字/窗口启动；本轮没有付费Provider消息或真语音验收。系统强制杀守护后的立刻自动清理不作保证，下次调用会重新建立守护；历史孤儿回收、原生PortAudio崩溃根治、音频管家隔离、任务现场恢复仍按长期手册OPS-01/06等单独规划，不能把正常会话退出的进程树清理扩大宣称为任意历史孤儿都可识别回收。未改Windows自启、全局执行策略或系统配置。
